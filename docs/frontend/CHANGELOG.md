# API Changelog

Contract changes that affect the frontend. 💥 BREAKING means frontend code must change. See [openapi.json](openapi.json) for the contract snapshot and [error-codes.md](error-codes.md) for error codes.

## 2026-10-17

- `GET /api/notifications/unread-count` stops counting at 100: `count` is at most `100`, which means 100 or more unread (show it as "99+"). Below 100 the number is unchanged.
- `GET /api/users/search` treats `%` and `_` in `username` as literal characters; `_` used to match any single character. Matching is otherwise unchanged (case-insensitive contains, any length).
- 💥 BREAKING The access token (`token`) now lives 15 minutes by default instead of 1 hour (`JWT_EXPIRATION_SECONDS` default 900), so a revoked role or a suspension takes effect sooner. Do not cache the token for a fixed hour: on 401, call `POST /api/auth/refresh` and retry, as described in [auth-flow.md](auth-flow.md).
- `POST /api/auth/google` verifies the ID token locally against Google's public keys (signature, `RS256` only, issuer, audience, expiry with 60 seconds of clock leeway) instead of calling Google's `tokeninfo` endpoint. Status changes: a malformed, wrongly signed, expired or non-Google token now returns 401 `auth.google.no_email` (was 500), and an unreachable Google key endpoint returns 503 `common.service_unavailable` (was 500, retry). A token issued for another client ID still returns 401 `auth.google.invalid_audience`. The server-side `GOOGLE_CLIENT_ID` now accepts comma-separated client IDs (see `.env.example`), so web and native clients can share the endpoint.
- Anonymous Ballots: `POST /api/votes/{voteId}/vote` accepts an optional `anonymous` boolean. An Anonymous Ballot is left out of `GET /api/votes/{voteId}/voters` whatever the Poll's `voterVisibility`, so that list can be shorter than `participantCount`; Turnout, the Invitee list's `hasBallot` and the caller's own `myOptionId` are unchanged. An omitted or `null` `anonymous` keeps the flag of the caller's current Ballot (also when changing option), and a first Ballot uses the caller's account default. Casting the same option again now updates `anonymous` (option counts and Turnout stay as they are). Existing Ballots are not Anonymous. Every Poll response gains `myBallotAnonymous` (nullable boolean): whether the caller's Ballot is Anonymous, null whenever `myOptionId` is null.
- `GET /api/votes/{voteId}/voters` returns 403 `vote.voters.hidden` while the Ended Poll holds 1 or 2 Anonymous Ballots other than the caller's own (otherwise the owner could work out who voted anonymously from the Invitee list); with none, or 3 or more, the list is returned as before. A Ballot cast after a Retraction starts again from `anonymousBallotByDefault`.
- Ballot writes and the other Poll changes (`POST /vote`, Retract, remove Selection, edit, close, delete, Invitee changes) now return 409 `common.conflict` when the Poll stays busy with other changes for 3 seconds; nothing is recorded, retry.
- Creating or editing a Poll now validates each option (`text` required and length limits) with the usual 400 `common.validation_failed`; such requests used to fail later.
- Account default: `PATCH /api/users/me` accepts `anonymousBallotByDefault` (`null` or omitted keeps it); `GET /api/users/me` returns it (`false` until set). Changing it does not touch Ballots already cast.
- `totalVotes` on `GET /api/users/{username}` and `GET /api/users/me` now counts only Ballots on Public Polls (not Deleted), matching `totalPolls`; Ballots on Unlisted and Invite-only Polls are left out, so the number can drop for existing accounts.
- Error envelopes for malformed requests: an unreadable or invalid JSON body returns 400 `common.bad_request`, a wrong HTTP method 405 `common.bad_request`, an unsupported `Content-Type` 415 `common.bad_request`, and a database uniqueness clash (e.g. a username taken between check and save) 409 `common.conflict`. These used to return 500 `common.internal_error`-style responses; other database constraint failures still return 500.
- Email / phone OTP: after 5 wrong codes the identifier is locked for 15 minutes; `send-otp`, `phone/send-otp` and both `verify-otp` calls return 401 `auth.otp.too_many_attempts` until then. When the OTP email or SMS fails to send, the resend cooldown is released so the user can retry at once, and `auth.email.send_failed` / `auth.sms.send_failed` no longer include the provider's error text.
- Apple sign-in returns 400 `auth.apple.not_configured` when the server has no `APPLE_CLIENT_ID`; previously any Apple token was accepted without an audience check.

## 2026-10-15

- Avatars everywhere: every response that names another user now also carries that user's avatar, in the same format as `user.avatarUrl` (`bot:<kind>`; older accounts may hold an image URL; null if never set). Avatars are always public. New fields, all nullable: `creatorAvatarUrl` on every Poll (`VoteResponse`: `GET /api/votes`, `GET /api/votes/{voteId}`, `GET /api/votes/my`, `GET /api/users/{username}/votes`, `POST` / `PUT` Poll and Ballot responses) and on `GET /api/votes/{voteId}/results`; `avatarUrl` on each `GET /api/votes/{voteId}/voters` item; `authorAvatarUrl` on Comments and Replies (null on a deleted placeholder, like `author`); `avatarUrl` on Invitees (`GET` / `POST` / `DELETE` `/api/votes/{voteId}/invitees`) and Group members (`/api/groups/{groupId}/members`), always null for one added by email.
- Reserved usernames: `PATCH /api/users/me` rejects a `username` equal to `search`, `account`, `explore`, `login`, `notifications`, `poll`, `sanity`, `api`, `admin` or `settings` with 400 `common.validation_failed` (field error on `username`), because profiles live at `/{username}` on the web and would shadow those routes. `me` and `my` are reserved too but already fail the 3-character minimum. The `[a-z0-9_]{3,50}` rule is unchanged, names that only contain a reserved word (e.g. `admin_1`) are allowed, and existing accounts that already hold a reserved name keep it (such an account gets the same 400 if it sends its current `username` back, so omit `username` when it is unchanged). Usernames generated at sign-up are never reserved.
- Avatars (the bot cast): `PATCH /api/users/me` accepts `avatarUrl`, which must be `bot:<kind>` with one of the 48 kinds of vomatt-web `src/features/avatars/catalog.ts` (`bot:boba` ... `bot:dog`); any other value returns 400 `common.validation_failed`. Omitted or `null` keeps the current avatar.
- `GET /api/users/me`, `GET /api/users/{username}` and the `PATCH /api/users/me` response gain `avatarUrl`. It is always public (no visibility setting) and `null` when never set. Accounts created before this change may still hold an image URL from Google / LINE.
- 💥 BREAKING New accounts (email OTP, phone OTP, Google, Apple, LINE) get a random `bot:<kind>` avatar at creation, so `avatarUrl` is no longer always an image URL: render `bot:<kind>` with the bot cast instead of `<img src>`. Google and LINE profile pictures are no longer copied into `avatarUrl`; avatars stored earlier are left as they are. `avatarUrl` in sign-in responses (`user.avatarUrl`) and `GET /api/users/search` items follows the same rules.

## 2026-10-14

- 💥 Suspended accounts: any authenticated request other than GET / HEAD / OPTIONS (outside `/api/auth/**`) from a suspended user now returns 403 `auth.account_banned`, even while the access token is still valid. Reads are unaffected. Treat it like a failed sign-in: clear tokens and show the suspension notice.
- Ballot writes (`POST /api/votes/{voteId}/vote`, `DELETE /api/votes/{voteId}/vote`, `DELETE /api/votes/{voteId}/vote/{optionId}`) are limited per account: more than 30 within 60 seconds returns 429 `common.rate_limited` (no `Retry-After` header) until the window resets. The per-IP write limit is unchanged.
- Gmail addresses are stored and returned in canonical form: for `gmail.com` and `googlemail.com`, the local part loses everything from the first `+` and every dot, and the domain becomes `gmail.com` (e.g. `A.B+news@googlemail.com` -> `ab@gmail.com`). This applies everywhere an address is accepted (email OTP, Google / LINE / Apple sign-in, check-email, `inviteeEmails` / `emails` on Polls and Groups, `?email=` removals), so every variant of one Gmail inbox signs in to the same account and matches the same email Invitee or Group member. Responses (`email` on login, profile, Invitee and Group member items) carry the canonical address. Other domains are still only trimmed and lower-cased.
- 💥 BREAKING Phone numbers are normalized to E.164 on `POST /api/auth/phone/send-otp` and `POST /api/auth/phone/verify-otp`: spaces, `-`, `(` and `)` are ignored, a Taiwan mobile number `09xxxxxxxx` becomes `+8869xxxxxxxx`, and a `+` number (country code plus 8-15 digits in total) is kept. `0912345678` and `+886912345678` are now the same number, one OTP and one account, so an OTP sent to one form verifies with the other. Any other format returns 400 `auth.phone.invalid`. `phoneNumber` in auth and profile responses is E.164 for new and migrated numbers (existing `09xxxxxxxx` numbers are migrated to `+886...`; a number skipped by the migration because its `+886` form already belongs to another account keeps its old value until the accounts are merged).
- Invite-only auto-end: an Open `INVITE_ONLY` Poll Ends as soon as every Invitee holds a Ballot, after `POST /api/votes/{voteId}/vote`, `DELETE /api/votes/{voteId}/invitees/{userId}` or `DELETE /api/votes/{voteId}/invitees?email=` (removing the last Invitee without a Ballot while at least one remains). The owner's own Ballot never counts, a pending email Invitee (not yet tied to a user) keeps the Poll Open, and a Poll with no Invitees never auto-ends. Verifying an email can also end it, when the verified address's pending row was the last one blocking and is dropped because that user was already invited by ID or owns the Poll. It ends like a Close: `endTime` moves to now, `deadline` stays, results unseal and the Ended Notification follows. Later Ballots get 400 `vote.ended`. Retract never ends a Poll. A remove-Invitee call runs the check even when it removes nothing, so it can end a Poll whose Invitees have all already voted.
- `POST /api/votes/{voteId}/vote` can now return an unsealed, Ended Poll: when the Ballot was the last Invitee's, the response already carries `endTime` = now and per-option counts. Do not assume the Ballot response is always Sealed; read the status from `endTime` as on any other Poll response.
- Groups: new owner-only `/api/groups` endpoints for private, reusable invite lists. `GET /api/groups` lists the caller's Groups by name (`id`, `name`, `memberCount`, `createdAt`); `POST /api/groups` (`{ "name": ... }`, 1-50 characters) creates one (201; at most 50 Groups per owner, else 400 `group.max_reached`); `PUT /api/groups/{groupId}` renames it; `DELETE /api/groups/{groupId}` deletes it. `GET /api/groups/{groupId}/members` lists the members, `POST /api/groups/{groupId}/members` (`{ "userIds": [...], "emails": [...] }`, each at most 100, at least one non-empty) adds them, `DELETE /api/groups/{groupId}/members/{userId}` and `DELETE /api/groups/{groupId}/members?email=...` remove one (idempotent); all three return the full member list (`userId`, `username`, `email`, `addedAt`). A Group holds at most 100 members (400 `group.members.max`). Members follow the Invitee rules: duplicates, existing members and the owner's own ID / address are ignored, unknown or suspended user IDs return 400 `group.member.ids_invalid`, and a member added by email is always listed only by that address (`userId` / `username` `null`), also once someone verifies the address at sign-up / sign-in and it is tied to that user. Members are never notified. Another user's Group, or one that does not exist, is 404 `group.not_found` on every path, never 403.
- `POST /api/votes`, `PUT /api/votes/{voteId}` and `POST /api/votes/{voteId}/invitees` accept `groupIds` (at most 20, no null elements) next to the Invitee lists; `groupIds` alone now satisfies the "at least one" rule of `POST /api/votes/{voteId}/invitees`. The Groups' current members are copied into the Poll's Invitees with the usual rules, notifications and invitation emails: members added by ID as users (suspended ones are skipped), members added by email as email Invitees by their stored address. Later Group edits or deletion never change the Poll. On edit, the members are merged into `inviteeIds` / `inviteeEmails` when that list is set, so an explicit `[]` plus `groupIds` replaces that kind of Invitee with the Groups' members (already-invited members are kept as they are); a `null` list keeps that kind of Invitee and adds the Groups' members on top. A missing Group or someone else's is 404 `group.not_found`; `groupIds` on a Poll that is not `INVITE_ONLY` returns 400 `vote.invitee.not_invite_only`.
- Invitations: a user added as an Invitee of an `INVITE_ONLY` Poll (on create, edit or `POST /api/votes/{voteId}/invitees`) gets an unread Invitation while the Poll is Scheduled or Open. It counts in `GET /api/notifications/unread-count`, shows as `unread: true` on that Poll in My Polls `status=open` (previously `unread` was always `null` on that tab; it is now `true` / `false` on every item), and is cleared with `POST /api/notifications/{voteId}/read`. Each Poll gives at most one notification at a time: once the Poll Ends, the Invitation is replaced by the Ended Notification, which is unread again even if the Invitation was read. Mark read reads whichever notification is current when the call arrives, so a mark read for the Invitation sent after the Poll Ended reads the Ended Notification. A removed Invitee loses the Invitation, and gets it unread again if invited again; a Deleted Poll gives neither notification. `POST /api/notifications/{voteId}/read` now also succeeds for an Invitee of a not-yet-Ended `INVITE_ONLY` Poll (instead of 404 `notification.not_found`).
- `GET /api/votes` accepts `sort=top` (Top) with `status=open` (or omitted `status`): Open Public Polls by Turnout (`participantCount`) highest first, ties most recently opened first. Combines with `tag` and `q` and pages by cursor like the other orderings; its cursors are accepted only by `sort=top`. `sort=top` with `status=ended` returns 400 `vote.list.sort_not_allowed`. Any other `sort` value still returns 400 `common.invalid_sort`.
- Ballots (cast, change, Retract, remove Selection) on the same Poll now run one at a time, because each one updates the Poll's Turnout; responses are unchanged.
- Email Invitees: `POST /api/votes` and `PUT /api/votes/{voteId}` accept `inviteeEmails`, and `POST /api/votes/{voteId}/invitees` accepts `emails` next to `userIds` (each at most 100, no null elements, valid addresses; at least one of `userIds` / `emails` must be non-empty, otherwise 400 `common.validation_failed`). Addresses are lower-cased and trimmed like sign-in. An address never reveals whether it has an account: every address is kept as an email Invitee, shown only by that address, and is sent an invitation email linking to the Poll; an address of an active account also gives that user access right away, and any other (unknown or suspended) is a pending email Invitee. `emails` / `inviteeEmails` never cause 400 `vote.invitee.ids_invalid`. The owner's own address is ignored. The invitation email links to the Poll (`EMAIL_SITE_URL` + `EMAIL_POLL_PATH`, default `/votes/{voteId}`; nothing is sent when `EMAIL_ENABLED=false`). Each address gets a Poll's invitation at most once, even after it is removed and re-added; an owner triggers at most `EMAIL_INVITATION_DAILY_LIMIT` (default 200) invitation emails per UTC day, and over that limit the Invitee is still added and only the email is skipped. On edit, `inviteeEmails` replaces the email Invitees (matched by address, whether or not tied to a user) and `null` keeps them; `inviteeEmails` on a Poll that is not `INVITE_ONLY` returns 400 `vote.invitee.not_invite_only`.
- A pending email Invitee grants nobody access. When someone verifies that address (email OTP sign-up / sign-in, Google or Apple with a verified email, or LINE, which only returns verified emails) it is tied to that user, still listed by the address: the Poll shows up in their My Polls and they can see it and cast a Ballot. An unverified Google / Apple email never binds.
- 💥 BREAKING Invitee list items (`GET` / `POST /api/votes/{voteId}/invitees`, `DELETE` removal) gain `email`. An Invitee added by email always has `email` set and `userId` / `username` `null`, for its whole life (also once tied to a user; `hasBallot` turns `true` once that person casts a Ballot), so `userId` is no longer always present. One added by ID has `email: null`. `inviteeCount` includes email Invitees.
- New owner-only `DELETE /api/votes/{voteId}/invitees?email=...` removes an Invitee added by email, also one tied to a user (400 `vote.invitee.has_ballot` when that user holds a Ballot). It follows the same rules and response as `DELETE /api/votes/{voteId}/invitees/{userId}` and is idempotent; `DELETE /api/votes/{voteId}/invitees/{userId}` removes only Invitees added by ID.
- Invite-only Polls: `audience: "INVITE_ONLY"` is now accepted on `POST /api/votes` and `PUT /api/votes/{voteId}` (the error `vote.audience.unsupported` is removed), together with `inviteeIds` (user IDs, e.g. from `GET /api/users/search`). Duplicates and the owner's own ID are ignored. At most 100 IDs, no null elements (400 `common.validation_failed`). Unknown or suspended users return 400 `vote.invitee.ids_invalid`; `inviteeIds` on a Poll that is not `INVITE_ONLY` returns 400 `vote.invitee.not_invite_only`. On edit, `inviteeIds` replaces the Invitees, `null` keeps them, and switching to another Audience removes them.
- Only the owner and the Invitees can reach an `INVITE_ONLY` Poll. Everyone else, signed out included, gets 404 `vote.not_found` on every single-Poll endpoint (Poll, Ballot, results, voters, my-vote-status, Comments, Replies, likes, notification read, Close, edit, Delete, Invitees). The Poll never appears in Feed / Explore / Search, profile lists or `totalPolls`, and its tags do not count in `usageCount`.
- My Polls (`GET /api/votes/my`) also lists Polls the caller is an Invitee of. Invitees receive the Ended Notification (unread count, `unread` on My Polls `status=ended`, mark read) even when they never cast a Ballot.
- New owner-only endpoints: `GET /api/votes/{voteId}/invitees` returns the Invitees, each with `hasBallot`. `POST /api/votes/{voteId}/invitees` (`{ "userIds": [...] }`, 1-100 IDs) adds Invitees; users already invited are ignored. `DELETE /api/votes/{voteId}/invitees/{userId}` removes one; it is idempotent and refused with 400 `vote.invitee.has_ballot` when that Invitee holds a Ballot. Add and remove return the full list and need the Poll to be `INVITE_ONLY` (400 `vote.invitee.not_invite_only`) and not Ended (400 `vote.ended`); non-owners get 403 `vote.forbidden`.
- Poll response gains `inviteeCount`: the number of Invitees of an `INVITE_ONLY` Poll, visible to everyone who can see it; `null` for other Audiences.
- Voter Visibility `SIGNED_IN` now means "anyone who can see the Poll". Nothing changes for Public and Unlisted Polls; on an Invite-only Poll it covers only the owner and the Invitees.
- Poll response gains `deadline`: the end time the owner set (`endTime` on create / edit sets both). Ending early moves only `endTime`, so `endTime` < `deadline` means the Poll ended early. Polls that ended early before this change have `deadline` equal to `endTime`. `GET /api/votes/{voteId}/results` gains the same `deadline` field.
- 💥 BREAKING `PUT /api/votes/{voteId}/deactivate` (Close) on an Open Public Poll returns 400 `vote.close.public_not_allowed`; a Public Poll runs to its Deadline (ADR 0004). Only Open Unlisted and Invite-only Polls can be Closed.
- 💥 BREAKING Close on a Scheduled Poll returns 400 `vote.close.scheduled` instead of cancelling it; use `DELETE /api/votes/{voteId}`. Cancelled Polls are no longer produced; existing ones stay Ended. Close on an Ended Poll is still a no-op success.
- Polls gain an Audience: `POST /api/votes` and `PUT /api/votes/{voteId}` accept `audience` (`PUBLIC` default, `UNLISTED`, or `INVITE_ONLY`, see the Invite-only entry above); omitting it keeps `PUBLIC` on create and the current value on edit. Audience can change only while the Poll is Scheduled (edit of an Open or Ended Poll is already 400 `vote.not_editable`).
- Poll response gains `audience` (`PUBLIC` / `UNLISTED` / `INVITE_ONLY`). Existing Polls are `PUBLIC`.
- An `UNLISTED` Poll is reachable only through its link: anyone can read it, any signed-in user can cast a Ballot and Comment, exactly like a Public Poll. It never appears in Feed / Explore / Search, the owner's profile list or `totalPolls`, and its tags do not count in popular tag `usageCount`. It is listed in My Polls for its owner and its Participants.
- 💥 BREAKING `GET /api/users/search` items (`UserDto`) now carry only public profile fields: `id`, `username`, `displayName`, `avatarUrl`. `email`, `phoneNumber`, `firstName`, `lastName`, `location`, `points`, `membershipLevel`, `active`, `createdAt` and `lastLoginAt` are removed. `displayName` is `null` when the owner hid it on the public profile. Ordering, cursor paging and the blank-`username` error are unchanged.
- 💥 BREAKING A pagination cursor is accepted only by the list and ordering that issued it. Sending it to another list or ordering (e.g. a Feed `sort=newest` cursor to `sort=closing`, a My Polls `status=open` cursor to `status=ended`, a comments cursor to replies) returns 400 `common.cursor_invalid`; restart from the first page. Changing `tag` or `q` with the same ordering is still allowed. Cursors issued before this change are no longer valid. Response shapes are unchanged.
- Casting, Retracting and removing a Selection racing a Close now either count before the Poll Ended or fail with 400 `vote.ended`; Ballots and counts never change after Close returns. Editing a Scheduled Poll that opened and received a Ballot meanwhile fails with 400 `vote.not_editable`; a Ballot on an option replaced by an in-flight edit fails with 404 `vote.option.not_found`.
- Added `DELETE /api/votes/{voteId}` (owner only): Deletes a Poll while it is Scheduled, or within the delete window after posting (default 20 minutes, configurable) even if it holds Ballots. Returns 400 `vote.delete.window_passed` outside that window, 403 `vote.forbidden` for a non-owner. Nobody is notified.
- A Deleted Poll is gone for everyone, owner included: every single-Poll endpoint (Poll, Ballot, results, voters, my-vote-status, Comments, Replies, Comment edit / delete / like, notification read, Close, edit) returns 404 `vote.not_found`, and it leaves Feed / Explore / Search, profile lists and `totalPolls`, My Polls, Ended Notifications (unread count) and popular tag counts.
- Poll response gains `deletable` (boolean): whether the owner can still Delete the Poll. Set on every Poll response to the owner (get, lists, create, edit, Ballot, Close); null for other callers.
- Profile `totalVotes` no longer counts Ballots in Deleted Polls.
- 💥 BREAKING `GET /api/votes/{voteId}/my-vote-status` (deprecated) returns 404 `vote.not_found` for an unknown or Deleted Poll instead of `hasVoted: false`.
- 💥 BREAKING `POST /api/notifications/{voteId}/read` returns 404 `vote.not_found` (instead of `notification.not_found`) when the Poll does not exist or is Deleted.

- `PATCH /api/users/me` accepts `username` (3-50 characters of `[a-z0-9_]`, not `search`); returns 409 `user.username.taken` when another account uses it. The old `/api/users/{username}` path returns 404 after the change.

## 2026-10-12

- Deprecated (still working, to be removed in a later 💥 release): `DELETE /api/votes/{voteId}/vote/{optionId}` → use `DELETE /api/votes/{voteId}/vote`; `GET /api/votes/{voteId}/my-vote-status` → use `myOptionId` in `GET /api/votes/{voteId}`.
- Write requests under `/api/votes/**` and `/api/users/**` (POST / PUT / PATCH / DELETE) are now rate limited per IP, with a counter separate from `/api/auth/**`, and may return 429 `common.rate_limited` with `Retry-After`; GET requests are not limited.

## 2026-10-09

- 💥 BREAKING 401 / 403 responses (filter layer) now carry an `ApiResponse` body with `errorCode` (previously the body was empty): `common.unauthorized`, `auth.token.expired`, `auth.token.invalid`, `common.forbidden`. The frontend uses `errorCode` to decide whether to refresh (see [auth-flow.md](auth-flow.md)).
- 💥 BREAKING 429 response body is now an `ApiResponse` (`errorCode` = `common.rate_limited`) and includes a `Retry-After` header (seconds), readable cross-origin. If the rate limiter itself fails, auth endpoints return 429 without `Retry-After`.
- Docs no longer list `zh-CN`: `Accept-Language` supports `zh-TW` (default) and `en`.
- 💥 BREAKING Swagger UI and `/v3/api-docs` are disabled by default; set `SWAGGER_ENABLED=true` to enable them (never enabled in production). The frontend should use [openapi.json](openapi.json) instead.
- The contract source is now `docs/frontend/openapi.json` (generated by tests); the old root-level `openapi.yaml` (from the Next.js era) is archived in `docs/archive/` and no longer maintained.
- All OpenAPI `summary` / `description` / `@Schema` text is now in English, and every endpoint documents auth, preconditions, side effects, errors, and examples.
- OpenAPI: every 2xx response now has a response schema; endpoints returning 201 (create Poll, create comment / reply, admin create lookup item) no longer also list a 200.
- OpenAPI version changed to 3.0 (`nullable: true` is emitted correctly; 3.1 drops it), so nullable fields in generated TS types are `T | null`.
- Comments and replies are readable without login: `GET /api/votes/{voteId}/comments` and `GET /api/votes/{voteId}/comments/{commentId}/replies` are public endpoints (posting and liking still require login).
- Public Poll paths only match UUIDs: `GET /api/votes/{voteId}` is public, while named sub-paths such as `GET /api/votes/my` still require login.
- Profile visibility defaults: when unset, `visibilitySettings` reports `displayName` and `bio` as public.
- Added `GET /api/users/{username}/votes` (public): Poll list for a user's public page, containing only opened Polls (Open, Ended), cursor-paginated.
- 💥 BREAKING The public profile now applies the `displayName` and `bio` visibility settings: returns `null` when hidden (previously always returned).
- 💥 BREAKING The public page and Poll list of a suspended user return 404 `user.not_found`.
- `totalPolls` (public page and `/api/users/me`) only counts opened Polls, excluding Scheduled ones and ones cancelled before opening.
- `/api/users/search/**` sub-paths also require login.
- Fix: new comments are no longer wrongly marked as `edited`; the `edited` of a deleted-comment placeholder is always `false`.
- Fix: editing a Scheduled Poll without `startTime` keeps the original start time.
