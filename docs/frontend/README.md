# Vomatt API Frontend Integration Guide

## Where to find what

| Content | Where to look |
|------|----------|
| Paths, parameters, fields, types, and error examples of a single API | Swagger (`/swagger-ui.html`, `/v3/api-docs`) |
| Flows spanning multiple APIs, global conventions, glossary | The Markdown files in this directory |

Swagger is the single source of truth for the spec; the Markdown files do not repeat fields and only link back to Swagger.

## Running the API locally

One command, only Docker required (no JDK, no `.env`):

```bash
docker compose up -d --build
```

- API: <http://localhost:8080> (CORS allows `http://localhost:3000` and `http://localhost:5173`; override with `CORS_ALLOWED_ORIGINS=... docker compose up -d`)
- Swagger UI: <http://localhost:8080/swagger-ui.html>
- OpenAPI JSON: <http://localhost:8080/v3/api-docs>
- Login: emails are not sent locally. After `POST /api/auth/send-otp`, read the code with `docker compose exec redis redis-cli GET otp:email:<email>`
- After pulling backend changes: run the same command again (`--build` rebuilds the image)
- Reset all data: `docker compose down -v`

Older Docker installs (e.g. OrbStack without the compose plugin) use `docker-compose` instead of `docker compose`.

Swagger is not available in production.

## Generating TypeScript types

The contract snapshot [openapi.json](openapi.json) is generated by `OpenApiSnapshotTest` (do not edit by hand); you can generate types from it even when Swagger is disabled:

```bash
npx openapi-typescript docs/frontend/openapi.json -o src/api/schema.d.ts
```

The old root-level `openapi.yaml` (a Next.js-era artifact) has been removed; do not use it.
